项目名称：beat
项目描述：用于监控服务器节点的监控运维服务
后端技术栈：
  1. 使用Go作为后端
  2. 存储使用 github.com/openmts/mts 作为时序数据库存储引擎
  3. 结构化数据使用sqlite来存储 使用pure go的开源库modernc.org/sqlite
前端技术栈：
  1. 使用React作为前端
  2. 使用shadcn/ui作为UI框架
前台布局要求：
  1. 头部header区域，左侧是文字LOGO，右侧是dark/light mode按钮，中英文切换按钮，后台管理按钮
  2. 主体区域展示节点的卡片信息，卡片上展示节点的综合信息，包括当前的CPU/MEM/DISK/NETWORK等等，点击卡片后，进入节点的监控指标展示页面，可以像grafana一样，展示节点的各个维度的折线图信息
  3. 由于节点存在分组的概念，主体区域默认展示所有节点，可以通过tab切换不同的分组
后台管理布局要求：
  1. 左侧是抽屉式导航栏，可以隐藏和展开
  2. 头部header区域，左侧是文字LOGO，右侧是dark/light mode按钮，中英文切换按钮
  3. 第一个标签页是"分组管理"，可以对节点的分组进行管理，创建分组，删除分组，重命名分组，分组排序等。存在一个默认分组，当分组被删除后，分组下的所有节点信息归属到默认分组下，默认分组不可以被删除，但是默认分组可以被切换到其他分组上，所以可以指定默认分组
  4. 第二个标签页是"节点管理"，可以对agent上报上来的节点进行管理。主要是可以给节点指定节点别名，分配节点的分组，给节点下发SSH公钥等
  5. 第三个标签页是"SSH密钥"，可以导入SSH密钥，可以生成SSH密钥，这个密钥可以分发给各个节点，做基于SSH密钥的免密登录
  6. 第四个标签页是"终端管理"，这个页面使用xterm.js来连接终端，快速进行SSH终端会话的建立；还可以在这个页面批量下发执行命令
  7. 第五个标签页是"告警管理"，可以对节点的指标进行告警配置，创建告警规则，创建告警通道，将触发了告警规则的事件推送到告警通道中
agent采集进程要求:
  1. 作为项目的子项目，代码按照Go的最佳实践放置在cmd目录下，进程名称为beat-agent
  2. beat-agent 的CLI框架使用urfave/cli，启动参数通过配置文件的形式提供，进程只暴露一个config的参数用来指定配置文件所在位置
  3. agent主动采集节点的各类运维指标，上报到beat服务端的采集端点API上
